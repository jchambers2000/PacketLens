# Security Policy

## Reporting a vulnerability

Do not disclose a suspected vulnerability in a public issue before the project owner can review it.

This project does not yet publish a dedicated security contact address. Use GitHub private vulnerability reporting if it is enabled. If it is unavailable, open a minimal public issue asking the maintainer to establish a private channel; do not include exploit details, packet captures, credentials, personal information, or sensitive evidence.

Include the affected version, operating system, reproducible steps, expected and observed behavior, and the minimum sanitized evidence needed. Never test against networks, devices, or data without authorization.

Reports may cover capture parsing, local reports, packaged dependencies, unsafe file handling, unintended network activity, privilege behavior, or disclosure of capture-derived data. Heuristic false positives or false negatives are not, by themselves, software vulnerabilities.
